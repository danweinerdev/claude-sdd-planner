## Spec-Driven Development

Planning artifacts live at `{{PLANNING_ROOT}}/`, configured by `planning-config.json`. Use the installed `sdd-planner` skills for research, specifications, designs, plans, implementation, review, debriefs, and validation.

Keep artifact status in YAML frontmatter. Plan and implement each task as one clean, complete, independently bisectable native SCM revision/checkpoint; subtasks are mechanical steps inside that boundary. Review each task's complete diff before finalizing that revision and preserve complete task state in the lifecycle record. Update task status and subtask checklists only after verification commands have actually run and the task's completion-evidence section records exact commands/tools, context, revision/checkpoint, result, and observable evidence. Write artifacts and ledger entries in-flow when facts are known; this never implies an immediate commit. **Git adapter:** in commit-capable workflows where commits are authorized, commit the verified feature slice first, then record once per affected root at task closeout—never per edit or as intermediate SDD-only commits. Shared-root artifacts and ledgers use one boundary commit; external roots record once at the same boundary. The same per-root rule applies to a contiguous spec/design/plan session and to phase/ready plan close (D-0019). Dirty or no-SCM work remains non-complete. Phase completion requires aggregate evidence plus a persisted, frozen, final `Aligned` run of all four `sdd-code-review` lanes. Material changes after review require a fresh full run. Before implementation, read the active plan and phase; after material changes, run the `sdd-code-review` skill.
